# 技能定義と用途設定の分離

## 調査結果と実装範囲

調査対象の基準コミット: `9125b07`。

従来の `rules/usage-skill-sync.mjs` は、親技能の式で用途自身の式を上書きし、現在・過去の技能の識別キーと `source` が一致する修正行を削除していた。`source` は帰属表示用であり、自動生成の証拠ではない。式本文が参照先を決める。

書き換え経路は次のとおりだった。

| 経路 | 従来の動作 | 今回の動作 |
| --- | --- | --- |
| `prepareUsageContext` | 表示前に用途を同期・保存 | 保存入力と読取専用の実効設定を別々に表示 |
| `updateUsageActions` | あらゆる用途保存で技能設定を同期 | 呼出元が指定した変更だけを保存 |
| `registerUsageSkillSync` | 技能作成・更新・削除で関連用途を保存 | 開いている用途エディタを再描画 |
| `TnxUsageSheet._patchUsage` | 技能追加時に式とフラグを複写 | 技能参照だけを保存 |
| 用途作成 | 親技能の式・許可を用途に複写 | 新形式を明記し、技能分は実行時に導出 |
| `activateItemCheck` | コピーを同期して実行 | 共通の純粋関数で実効値を取得 |
| 再判定 | 実効修正行から再び同期 | 用途固有入力のスナップショットから再導出 |

画面表示時の必須コンボ補完とパリー武器の保存も撤去した。新規用途の初期補完、技能の追加・削除・明示的な設定変更時の補完は維持する。パリー武器の初期値は用途作成時に設定し、既存用途を開いただけでは武器参照を追加しない。

対象・射程・タイミング・対決・消費・AE参照・用途タイプの決定、式の数値評価、重複参照による採否は既存処理を維持する。今回、これらを技能変更へのライブ追従に拡張していない。

## 保存と解決

`settingsVersion: 1` の用途では従来の用途フィールドを用途固有設定として使用する。技能の定義値はアイテム本体を参照し、用途の保存欄へ複写しない。

`resolveUsageSettings(usage, parent, getItem)` は文書更新・グローバル参照・式評価をしない。返却値は次のとおり。

- `local`: 用途固有の入力。
- `contributions`: 現在の参加技能に由来する修正行。
- `effective`: 実行に使用する設定。用途固有入力の `usageSettingsInput` スナップショットを含む。
- `diagnostics`: 旧形式、式の参照に必要な識別キー欠落などの診断。

参加技能は親・ベース・組み合わせのアイテムIDの和集合とし、重複参加を除く。技能の用途一覧は参照しない。再判定カードには用途固有入力を引き継ぎ、現在の参加技能の定義を再解決する。カード内の実効行を用途固有行として取り込まない。

修正行の `origin.kind` は `usage` または `skill`。技能行には `itemId` と定義元フィールド、用途行には元の配列と位置を付ける。これは実効値の来歴であり、既存保存行の来歴を後付けで断定するものではない。`source` が一致しても手動行を削除しない。

## 合成規則

| 設定 | 規則 |
| --- | --- |
| 判定・ダメージ修正 | 用途自身の式、用途の修正行、参加技能の修正行を保持。数値の合計・重複制御は既存の式評価処理に委譲 |
| ダメージ修正の対象条件 | それぞれの式に付随する条件を保持。他の式や用途全体の条件で上書きしない |
| ヴィークル準備条件 | 用途または参加技能に要求があれば必要。許可とは区別して扱う |
| 再判定・スート変更・スタン・割り込みの許可 | 用途固有の許可と、当該用途タイプに適用できる技能の許可の和集合 |
| 割り込みのAR消費 | 割り込みを許可する供給元のうち一つでも消費ありなら消費。2026-11-15のユーザー確認で現行規則を維持 |
| ダメージ種別候補 | 用途固有の選択・候補と技能の候補の和集合。用途の明示選択を優先し、未指定時は従来の技能順。技能由来候補がなくなった再判定では元の武器種別に戻せるよう別に保持 |

用途タイプごとの適用可否は `styleSkillUsageDefaults` に集約する。用途で許可をオフにしても技能の許可を打ち消す「禁止」にはしない。新しい禁止機構や条件間の優先順位は導入しない。

## 既存用途の保全・個別移行・復元

旧形式の親技能由来式は用途自身の式と混ざり、上書き前の値が残っていないことがある。`skillSettingsSync.local`、一致する式、識別キーから完全な来歴は復元できない。

2026-11-15のユーザー確認に従い、旧用途は保存値をそのまま使用し「要確認」と表示する。参加技能の設定変更による自動同期は停止する。新規用途または確認して移行した用途のみ新方式で導出する。

1. 診断: `diagnoseUsageSettings`。保存しない。
2. 移行: エディタの「設定の来歴を確認して移行」で各値・各修正行の扱いを指定する。未選択では実行しない。「用途固有として保持」は残し、「技能から導出」は用途固有分から外す。保持を選んだ値と現在の技能分が両方適用される点に注意する。
3. 保存: 明示的な決定を `migrateUsageSettings` に渡し、用途全体の移行前コピーを `settingsBackup` に保存する。確認中に用途が変更されていれば移行を中止する。
4. 復元: 「移行前の用途全体を復元」でバックアップへ戻す。移行後の編集も戻ることを確認画面で明示する。復元対象は用途であり、削除された技能アイテムは復元しない。

過去の上書きで失われた値そのものは、このバックアップでは復元できない。必要なら変更前のワールドバックアップやエクスポートとの照合が必要。今回、ワールド・パックの一括変換は行わない。
